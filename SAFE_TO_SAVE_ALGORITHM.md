# Safe-to-Save

## Назначение

`Safe-to-Save` ежедневно считает, какую сумму можно безопасно перевести с основного счета на накопительный депозит, не создавая риск кассового разрыва до следующего ожидаемого дохода.

Алгоритм является серверной бизнес-логикой и выполняется на backend в [DailySavingsService.java](C:/Users/user/IdeaProjects/HackathonBank/src/main/java/com/example/hackathonbank/service/DailySavingsService.java). Flutter только показывает результат и отправляет команды.

## Какие данные использует алгоритм

Для текущего пользователя backend берет:

- баланс основного счета
- баланс накопительного депозита
- список будущих `ScheduledPayment` со статусами `SCHEDULED` и `POSTPONED`
- завершенные транзакции за последние `30` дней для расчета среднего дневного расхода
- завершенные входящие транзакции за последние `90` дней для прогноза даты следующего дохода
- виртуальную дату из admin/demo mode, если он включен

## Формула

### 1. Защитный порог

Если баланс основного счета меньше `1000.00 KGS`, алгоритм сразу возвращает `0`.

```text
if mainBalance < 1000:
    suggestedAmount = 0
```

### 2. Дата следующего дохода

Backend пытается предсказать следующую дату дохода так:

1. Берет положительные транзакции за последние `90` дней.
2. Ищет повторяющийся день месяца, который встречается минимум два раза.
3. Если такой паттерн найден, строит следующую дату по этому дню месяца.
4. Если явного паттерна нет, считает средний интервал между входящими транзакциями.
5. Если данных совсем мало, использует fallback `+14 дней`.

### 3. Обязательные платежи

Суммируются все будущие `ScheduledPayment`, у которых:

- дата не раньше текущей даты
- дата не позже даты следующего дохода

```text
requiredPayments = sum(all scheduled payments due on or before nextIncomeDate)
```

### 4. Буфер на жизнь

Из завершенных транзакций за последние `30` дней берутся только расходы.

```text
averageDailySpend = totalExpensesLast30Days / 30
lifeBuffer = averageDailySpend * daysToNextIncome * 1.2
```

Коэффициент `1.2` добавляет консервативный запас.

### 5. Safe Balance

```text
safeBalance = currentMainBalance - requiredPayments - lifeBuffer
```

### 6. Сумма перевода

Если `safeBalance > 0`, переводится не весь остаток, а только `5%` от него.

```text
if safeBalance > 0:
    suggestedAmount = safeBalance * 0.05
else:
    suggestedAmount = 0
```

Все суммы округляются до `2` знаков после запятой.

## Что возвращает preview API

Эндпоинт:

- `GET /api/v1/ai/daily-safe-to-save`

Возвращает:

- `enabled` — включен ли автоматический ежедневный автосейв
- `suggestedAmount` — сколько можно безопасно отложить сегодня
- `safeBalance` — запас после вычета обязательств и буфера
- `currentBalance` — текущий баланс основного счета
- `requiredPayments` — сумма обязательных платежей до следующего дохода
- `lifeBuffer` — резерв на повседневные траты
- `nextIncomeDate` — прогнозируемая дата следующего дохода
- `daysToNextIncome` — горизонт до дохода в днях
- `status` — человекочитаемое объяснение результата

## Как работает автоматический ежедневный запуск

Планировщик находится в [DailySavingsScheduler.java](C:/Users/user/IdeaProjects/HackathonBank/src/main/java/com/example/hackathonbank/service/DailySavingsScheduler.java).

По умолчанию он запускается каждый день в `09:00`:

```text
app.daily-savings.cron = 0 0 9 * * *
```

Последовательность такая:

1. Выбираются все пользователи, у которых `autoDailySaveEnabled = true`.
2. Для каждого пользователя пересчитывается `suggestedAmount`.
3. Если сумма больше `0`, вызывается [TransferService.java](C:/Users/user/IdeaProjects/HackathonBank/src/main/java/com/example/hackathonbank/service/TransferService.java) и выполняется перевод:
   - с основного счета
   - на накопительный депозит
4. После перевода собираются завершенные транзакции за последние `3` дня.
5. Эти транзакции и сумма перевода передаются в AI-слой для генерации персонального уведомления.
6. Если live AI недоступен, используется fallback-текст.

## Какие API управляют фичей

- `GET /api/v1/ai/auto-daily-save`
  - возвращает текущий флаг `enabled`
- `POST /api/v1/ai/auto-daily-save`
  - включает или выключает автоматический ежедневный перевод
- `GET /api/v1/ai/daily-safe-to-save`
  - возвращает preview расчета на сегодня
- `POST /api/v1/demo/simulate-day`
  - сдвигает виртуальную дату на один день вперед и сразу запускает Safe-to-Save

## Как работает demo simulate-day

Эндпоинт:

- `POST /api/v1/demo/simulate-day`

Он нужен для хакатон-демо и делает ровно один контролируемый шаг:

1. Берет текущую effective date пользователя.
2. Сдвигает ее на `+1 день`.
3. Принудительно включает `adminModeEnabled = true`, чтобы расчеты шли от виртуальной даты, а не от системных часов.
4. Сразу запускает Safe-to-Save на новую дату.
5. Возвращает:
   - новую текущую дату
   - новый баланс основного счета
   - новый баланс накопительного депозита
   - сумму, которую удалось отложить в этот день
   - флаг `autoSaveExecuted`
   - текст уведомления

Важно: сейчас `simulate-day` симулирует именно Safe-to-Save и не занимается автоматическим исполнением всех запланированных платежей.

## Правила безопасности

- Если на основном счете меньше `1000 KGS`, перевод запрещен.
- Если после вычета обязательных платежей и life buffer запас не положительный, перевод запрещен.
- Переводится только `5%` от safe balance, а не весь safe balance.
- Источником истины всегда является backend.
- UI не должен самостоятельно пересчитывать сумму ежедневного автосейва по своей формуле.

## Короткий пример

Допустим:

- основной счет: `20 000 KGS`
- обязательные платежи до зарплаты: `4 000 KGS`
- средний дневной расход: `100 KGS`
- до следующего дохода: `5` дней

Тогда:

```text
lifeBuffer = 100 * 5 * 1.2 = 600
safeBalance = 20 000 - 4 000 - 600 = 15 400
suggestedAmount = 15 400 * 0.05 = 770
```

В этот день Safe-to-Save может безопасно перевести `770 KGS` на накопительный депозит.
